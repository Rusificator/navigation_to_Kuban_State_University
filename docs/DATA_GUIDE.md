# Данные и расширение

Контракт находится в `src/domain/types.ts`, проверка - в `src/data/repository.ts`. Пакеты хранятся отдельно от UI. `schemaVersion` относится к структуре; `version` - к конкретному выпуску карты. ID неизменяемы при переименовании помещений.

| Сущность | Что хранит | Правило |
|---|---|---|
| CampusPackage | ID, версия, название, адрес, источник, этажи | Один локальный связанный кампус; другой адрес не соединять искусственно |
| Building | Контурные границы, центр, этажи, входы | Границы используются всеми визуализаторами |
| Place | Названия/описания, категория, прямоугольник, входы, алиасы | Уникальный ID; несколько входов допустимы; пустые входы означают отсутствие маршрута |
| NavNode | x, y, этаж, среда | Координаты в системе пакета |
| NavEdge | Концы, стоимость, тип, направление, закрытие, доступность | Проходимость должна опираться на обследование |
| FloorGeometry | Контуры пола и стен SVG path | Только пути, без HTML, скриптов, внешних ресурсов |
| GeoReference | Аффинное преобразование, граница, масштаб, остаточная ошибка | Использовать как измеренную привязку только после обследования |

`source` содержит универсальные `name`, `version`, `uri`, `sha256`, `importedAt`, `verifiedAt`. Источником нового пакета может быть обследование или официальная схема, а не только APK. `Place.originalName` хранит исходную подпись/код; `searchable: false` скрывает технические безымянные зоны из поиска, сохраняя их на карте. В новом пакете без этого флага именованные места доступны поиску.

## Добавить аудиторию или корпус

1. Возьмите копию `src/data/campus.json` как образец; измените ID/версию/источник, не затирая исходный файл вручную при исследовании.
2. Добавьте Building/FloorGeometry и Place. Для новых этажей добавьте их в `floors` и соответствующий `Building.floors`.
3. Добавьте узлы именно у проверенных дверей и поворотов. Соедините проходимыми рёбрами. Сохраняйте временно закрытые рёбра с `closed: true`.
4. Укажите все входы помещения в `nodeIds`; алгоритм сам выбирает оптимальную пару входов. Нельзя привязывать объект к ближайшему узлу через стену.
5. Заполните RU/EN, алиасы номера, подпись источника и состояние проверки. Не превращайте недостоверную доступность в `yes`.
6. Импортируйте JSON через настройки (максимум 10 МБ), проверьте поиск и маршруты. Импорт текущей версии сессионный; для поставки в приложение замените встроенный пакет и соберите его заново.

2D и 3D используют границы нового пакета автоматически. Географический слой `outdoors.json` сейчас привязан к главному кампусу и при открытии другого пакета отключается. Подключение дополнительных географических пакетов требует адаптера наружного слоя и ID соответствующего кампуса; автоматически смешивать их с исходной картой нельзя.

## Добавить язык или изменить дизайн

Словари интерфейса собраны в `src/i18n/index.ts`, реестр языков — в `src/domain/localization.ts`. Для нового языка добавьте код, название и языковой тег в `localeCatalog`, затем полный словарь в `dictionaries`. Тип `Locale`, выбор языка и загрузка сохранённых настроек обновятся автоматически. TypeScript и тест всех зарегистрированных словарей проверяют полноту ключей.

Дополните `name`, `shortName`, `description`, `title`, `address` в пакете. Поиск учитывает все языки данных независимо от языка интерфейса. `localize` использует запрошенный перевод, затем английский, затем русский; старые пакеты продолжают открываться с новым интерфейсом. Контракт пакета сохраняет RU/EN как базовые поля. Все переводы при импорте проверяются на строковый тип. Для системных окон разрешений добавьте отдельные ресурсы Android/iOS в `scripts/configure-native.mjs`. Русская и английская версии уже включают весь текущий справочник; терминология перевода требует редакторского согласования.

Номер этажа — целое число: поддерживаются в том числе 0 и отрицательные значения. Переход на этаж 0 не трактуется как отсутствие перехода.

Оформление сосредоточено в CSS-переменных `--bg`, `--panel`, `--text`, `--muted`, `--accent`, `--line` и цветах категорий. Геометрия и поиск не зависят от темы. Для замены карты реализуйте `MapHandle` и входные Props компонента, не переписывая Router.

## Позиционирование

Сейчас `ForegroundLocation` принимает позицию только при открытом приложении и останавливает подписку при уходе в фон. Данные не отправляются на сервер и не сохраняются в историю. Разрешение запрашивается после действия пользователя.

GPS наружного слоя: преобразование долготы/широты в локальные метры около заданного origin; свежесть до 15 секунд, отклонение времени не более 5 секунд, радиус ошибки до 100 м для отображения. При ошибке свыше 35 м показывается предупреждение. Точка вне полигона кампуса не рисуется. Это картографическое приближение на масштабе одного кампуса, не геодезическая модель.

`domain/location.ts` содержит отдельную проверку обследованной привязки внутренних планов: качество до 35 м, перенос остаточной ошибки привязки, проверка границы. Она не используется для имитации indoor-позиции в интерфейсе. Даже после геопривязки GPS сам по себе не даёт этаж.

Следующий контракт позиционирования должен содержать `{point, floor, accuracy, source, timestamp}`; floor допускает unknown. Источниками могут быть ручная отметка у входа, QR-маяк, BLE/UWB или иной проверенный адаптер. До такого внедрения автопереход шагов и автоперестроение отключены.

## Воспроизводимость импорта

```sh
python3 -m pip install lxml
python3 scripts/import-apk.py /path/to/original.apk
python3 scripts/import-osm.py /path/to/campus.osm
```

APK-адаптер принимает только известный SHA-256. Он читает ZIP без извлечения путей, выделяет два заранее изученных модуля данных и выполняет их с ограничением времени/генерации кода. `node:vm` не считается универсальной защитной песочницей, поэтому произвольные APK этим адаптером обрабатывать нельзя: для новой версии требуется отдельный разбор до снятия ограничения хеша.

Перевод исходных описаний задаётся словарём `src/data/translations/en.legacy.json` по точному русскому тексту, поэтому не зависит от порядка записей. OSM-импортёр рассчитан на relation 4512079 и воспроизводит наружный пакет при том же входном XML. Обновление OSM может менять геометрию, поэтому новый результат сначала проверяется.

Для серверного обновления в будущем: immutable версии, контрольная сумма, подпись издателя, staging-проверка ссылок графа, атомарное переключение и rollback. Эти механизмы не подменяются текущим импортом файла и пока не реализованы.

## Слой уточнений 0.2

`src/data/curation.json` хранит проверяемые поправки, их источники и наружные объекты. Не редактируйте результат `campus.json` вручную: повторите `python scripts/import-apk.py /absolute/path/to/original.apk`. Исходный аудит и журнал исправлений разделены. Канонические номера берутся из `roomNames` APK; типовые названия санузлов/буфетов не являются уникальными ключами.

Для наружного `Place` задайте `environment: "outdoor"`, `floor: null`, `buildingId: null`, локальную рамку и, если проверены, `outdoorFeatureIds`. Нет проверенной двери — `nodeIds: []`. Короткая двуязычная подпись задаётся `mapLabel`. `catalogStatus: "unresolved"` скрывает неподтверждённый номер на схеме; `searchable: false` исключает запись из поиска, не удаляя геометрию. `parentBuildingId` связывает крыло с главным зданием без смены стабильных ID.

`evidenceSources`/`evidenceIds` отделяют происхождение фактов от источника базовой схемы. `NavEdge.instruction` задаёт обратимо сформулированный шаг перехода. `ContextShape.kind` отделяет здания от `track`, `field`, `marking`, `outline`; `transform` — шесть конечных чисел SVG matrix. Это преобразование рисунка, не GPS. Общий обзор учитывает `contextBounds`.
