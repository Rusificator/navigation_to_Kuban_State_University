# Переход от предварительной версии к университетскому пилоту

Сначала подтверждаем данные, затем оцениваем навигацию на устройствах. Не следует компенсировать недостоверную карту более убедительной анимацией.

## Порядок работ

| Приоритет | Работа | Критерий завершения |
|---|---|---|
| P0 | Получить актуальные поэтажные планы и согласовать обозначения корпусов с КубГУ | У каждого корпуса/этажа есть источник, дата и ответственный; расхождения А3/А4/Л разобраны |
| P0 | Проверить двери, переходы, лестницы и закрытия | Все опубликованные маршруты проходят по физически существующим и разрешённым проходам |
| P0 | Разобрать 35 зон без входов и изолированную пару узлов | Каждая запись исправлена или явно оставлена без маршрута; без случайного удаления альтернативных входов Н401 |
| P0 | Выполнить геопривязку и измерить масштаб | Контрольные точки покрывают кампус; есть независимые проверочные точки и оценка ошибки |
| P0 | Собрать и испытать Android/iOS на реальных устройствах | Пройден сценарий поиска и маршрута во всех темах/языках, режим отказа GPS и отсутствие WebGL |
| P1 | Подтвердить доступность без ступеней | Обследованы пандусы, пороги, лифты, ширины, режимы доступа; неизвестные рёбра не принимаются за доступные |
| P1 | Проверить справочник и переводы | Назначения помещений актуальны; английские названия согласованы; старые фамилии не показаны как текущие |
| P1 | Привязать наружные POI к маршрутам | Входы имеют проверенные координаты и связаны с графом; мемориалы не соединяются линией через ограждения |
| P2 | QR-контрольные точки и автоматическое сопровождение | Система знает точку/этаж и точность; есть пороги отклонения и явное восстановление позиции |
| P2 | Управляемые обновления карт | Подпись, версия, проверка связности, атомарная установка и возврат предыдущего пакета |

## Карточка обследования

Минимальные поля: стабильный ID объекта, корпус, этаж, подпись на двери, тип объекта, дата, сотрудник-проверяющий, источник плана, фотография вывески при разрешении, фактические входы, часы/условия доступа. Для перехода - тип, направление, закрытие, ступени, пороги, доступность, ширина и примечание. Не включать сведения, не нужные для навигации студентов.

Для геопривязки нужны минимум три неколлинеарные пары точек для аффинной модели, но минимального числа недостаточно для проверки качества. Собирать распределённые по территории точки, часть оставить вне подгонки. Фиксировать метод измерения и остатки; не подменять точную привязку координатой центра университета из поисковой карты. При локальных деформациях исходных планов использовать отдельные преобразования корпусов, а не растягивать весь кампус одним коэффициентом.

## Приёмочные прогулки

- Главный вход → А421: несколько поворотов и переход этажей.
- Н401: проверить каждый из трёх входов; отдельно установить смысл `node2132`/`node2133`.
- Две аудитории с одинаковым отображаемым номером/названием в разных блоках: выбор не должен путаться.
- Вход → библиотека, столовая, бассейн, музей: проверить наружные и внутренние участки.
- Маршрут к месту без входа: понятное сообщение, без нарисованного прохода через стены.
- Временное закрытие: соответствующее ребро исключено, альтернативный путь проверен на местности.
- Профиль без ступеней: пройти его с ответственным за доступную среду; алгоритмического исключения лестниц недостаточно.

Записывать расхождения как `placeId`/`edgeId`, координаты плана, описание, дату и результат повторной проверки. Встроенное «Сообщить об ошибке» сохраняет JSON в браузере или открывает системное меню «Поделиться» на телефоне. Автоматической отправки в университет нет.

## Устройства и UX

Минимальная матрица: небольшой Android 320-360 CSS px, распространённый Android среднего уровня, iPhone с вырезом, iPad; свежая и минимальная поддерживаемая ОС. Проверить портрет/альбом, safe areas, размер шрифта, VoiceOver/TalkBack, контраст, фокус и цели касания. На 3D измерить время открытия, пиковую память, нагрев и отзывчивость жестов; при проблемах сделать 2D начальным режимом для данного класса устройства.

GPS: разрешён / запрещён / приблизительный / службы выключены / устаревшая позиция / за пределами / переход в фон. Система не должна оставлять активную подписку после закрытия. Ни один тест не должен подтверждать этаж на основании одного GPS.

Для пилота критерии согласовываются с университетом: полный проход всех публикуемых связей, ноль маршрутов через стены/закрытые двери, стабильные сценарии без падений, корректный fallback карты, проверка сохранения избранного и языковых предпочтений после перезапуска. Подписание и публикация выполняются только после этих проверок и решения владельца проекта.
